# Skill Catalog and Routing

This is the human-readable view of `manifests/skill-catalog.json`. Availability says whether a capability is installed by this package, supplied by Codex Desktop, or usable only when already installed.

| Capability | Availability | Class | Stages | Select when | Do not select when |
|---|---|---|---|---|---|
| `engineering-task-workflow` | BUNDLED_CORE | CORE | ANALYZE, PLAN, IMPLEMENT, REVIEW, VERIFY, DELIVER | Any non-trivial repository engineering task. | Skip for simple questions or writing unrelated to a repository. |
| `intent-driven-development` | BUNDLED_CORE | CORE | ANALYZE, PLAN | Material ambiguity, high-impact product behavior, or acceptance criteria that cannot be inferred safely. | Do not add a discovery ceremony when the requested behavior and evidence are already clear. |
| `verification-before-completion` | BUNDLED_CORE | CORE | VERIFY, DELIVER | Before any claim that repository work is complete, fixed, or passing. | Requires fresh evidence for the current files; implementation alone never satisfies it. |
| `tdd-workflow` | BUNDLED_CORE | CORE | PLAN, IMPLEMENT, VERIFY | A behavior change, regression, or refactor where a focused automated test can fail meaningfully first. | Skip for documentation, generated artifacts, or tests that only mirror implementation. |
| `systematic-debugging` | BUNDLED_CORE | CORE | ANALYZE, IMPLEMENT, VERIFY | A reproducible bug, failing check, regression, or unexplained behavior. | This is the only general debugging workflow; use evidence and one falsifiable hypothesis at a time. |
| `database-migrations` | BUNDLED_CORE | CORE | PLAN, IMPLEMENT, VERIFY, DELIVER | Any persistent schema or data migration. | Covers rollout, compatibility, backfill, rollback, and real database verification; it does not replace engine-specific design guidance. |

## Overlap rules

- **debugging:** Use systematic-debugging as the sole general debugging workflow. Add click-path-audit only for a reproduced UI state-flow problem.
- **verification:** Use repository checks during work and verification-before-completion as the final evidence gate. Production-audit is reserved for a real release decision.
- **postgres:** database-migrations governs change lifecycle; supabase-postgres-best-practices governs PostgreSQL design and SQL. Use both for PostgreSQL migrations.
- **api:** api-design governs HTTP semantics, contract-first governs independently evolving boundaries, and backend-patterns governs supported server implementation.
- **frontend:** ui-ux-pro-max covers broad journeys, frontend-design covers visual direction, frontend-ui-engineering implements, framework skills refine stack behavior, and browser-qa verifies.
- **accessibility:** fixing-accessibility is for web; accessibility is optional and native. Select by platform rather than loading both.
- **security:** Use security-best-practices as the specialist review when its trigger matches. Do not stack redundant generic security skills; HIGH and CRITICAL work gets one fresh adversarial self-review.
- **assets:** brand defines identity constraints, frontend-design applies visual direction, imagegen creates raster assets, and Codex integrates and verifies them.

## Excluded automatic routes

`verification-loop`, `delivery-gate`, `context-budget`, `strategic-compact`, `debugging-strategies`, `coding-standards`, `postgres-patterns`, `security-review`, `security-scan`, `frontend-patterns`, `baseline-ui`, `ui-styling`, `frontend-design-direction`, `design`, `banner-design`, `product-lens`.

An excluded skill may exist on a machine for historical or manual use. Its presence does not make it eligible for automatic routing.
