# UI/UX Product Review

Use this capability for significant experience decisions, then route implementation to the stack-specific skill.

## Workflow

1. Identify the primary user, task, success condition, constraints, and evidence available in the repository.
2. Map the shortest complete journey and its decision points.
3. Review information hierarchy, navigation, content clarity, interaction feedback, error recovery, accessibility, responsive behavior, and trust signals.
4. Prioritize findings by user impact and implementation cost.
5. Convert accepted findings into observable acceptance criteria and concrete component or flow changes.
6. After implementation, inspect the runnable result and reverify changed paths.

## Boundaries

- Do not load this broad capability when a focused frontend, accessibility, motion, or browser-QA skill is sufficient.
- Do not invent research findings or user preferences.
- Do not add a design system or redesign adjacent flows unless the requested outcome requires it.
